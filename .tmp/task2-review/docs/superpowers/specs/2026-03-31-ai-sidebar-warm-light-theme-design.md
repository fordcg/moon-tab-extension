# AI Sidebar MVP 暖纸风亮色主题统一设计

## 背景

当前 `ai-sidebar-mvp` worktree 的 `newtab` 页面、AI 侧边栏和设置弹窗整体采用深色、冷调、轻玻璃感视觉语言。用户这次希望把整个 worktree 的用户可见页面统一改成 **明亮风格**，并明确选择了 **暖纸风** 方向，而不是冷白科技感或高光玻璃感。

这次不是产品重设计，也不是功能迭代，而是一次 **围绕现有结构做主题切换和轻量精修** 的 UI refinement：

- 范围：整个 `D:\proj\test\.worktrees\ai-sidebar-mvp` 的用户可见页面
- 风格：暖纸风亮色主题
- 深度：亮色切换 + 轻量精修
- 约束：尽量不改交互结构，不碰业务逻辑

## 目标

1. 把 `newtab`、AI 侧边栏、设置弹窗统一到同一套暖纸风亮色视觉系统。
2. 保留现有页面结构、状态类、交互流程和模块边界。
3. 提升阅读感，让页面更像“桌面上的 AI 阅读 / 搜索助手”，而不是冷黑科技面板。
4. 在亮色基础上精修卡片层次、边框、按钮质感、输入区和留白，但不做明显重设计。

## 非目标

1. 不新增功能。
2. 不调整 AI 调用、状态机、权限或存储逻辑。
3. 不重做 DOM 结构，除非仅为亮色主题适配做极小改动。
4. 不把页面改成完全不同的产品定位；仍然保留“AI 助手 / 搜索增强工具”的气质。

## 设计原则

### 1. 暖白胜过冷白
整体亮色不走纯白科技风，而是偏奶白、米白、浅杏、淡金棕的暖纸风，避免视觉过冷。

### 2. 纸感层次优先于玻璃感炫技
现有深色版本大量依赖半透明与冷调光感。亮色版应改为更像纸张叠层：

- 外层背景更柔和
- 面板像暖白纸面
- 阴影更软、更浅
- 边框存在但不抢眼

### 3. 保留现有结构，改表皮与节奏
用户已明确选择“亮色 + 轻量精修”，因此应保持：

- 现有布局结构
- 现有交互入口
- 现有状态切换方式
- 现有信息层级

主要改动集中在 token、组件表面样式、排版节奏和间距微调。

### 4. AI 感保留，但更安静
虽然改成暖纸风，但不能变成普通笔记页。仍需保留轻微的 AI 助手感，通过以下方式维持：

- 温和的强调色
- 精确的状态对比
- 输入区与消息区的产品感
- 局部保留柔和发光或高亮反馈，但只用在关键状态上

## 统一视觉系统

### 颜色基调
建议把当前深色 token 系统替换为以下暖色方向：

- 页面背景：奶白到浅米色渐变
- 主面板：暖白纸面
- 次级面板：更浅的米白 / 杏白
- 边框：低对比浅棕灰 / 浅米灰
- 主文字：深棕灰
- 次文字：灰棕色
- 强调色：柔和琥珀、淡金棕、鼠尾草灰棕中的一组稳定组合
- 错误态：保留偏暖红，但降低荧光感
- 成功态：保留柔和绿色，避免与整体暖纸风冲突

### 材质表现
统一使用以下表面语言：

- 大背景：柔和渐变，不再是深色发光星空
- 卡片：暖白纸感卡片
- 高层级卡片：边框略强、阴影略深
- 弹窗：像一张浮起的纸面弹层
- 输入区：像嵌在页面底部的柔和书写区

### 阴影与边框
- 阴影从“深而硬”调整为“浅而宽”
- 边框从冷蓝半透明线改为浅米灰描边
- 避免每个组件都重阴影；重点突出顶层弹窗、搜索容器和主操作按钮

## 页面级设计

## 1. `src/pages/newtab/index.html` + `src/pages/newtab/styles/index.css`

### 背景与主舞台
newtab 页面应从当前冷黑、夜空式背景切换为暖亮基底：

- `body` 和 bubble layer 的底色改成暖白 / 米白渐变
- 背景装饰仍可保留，但要从“夜间光晕”改成更柔和的暖色光斑 / 纸面氛围
- 设置打开时的 dimming 逻辑保留，但亮色下应改成轻微降饱和和柔化，而不是明显压暗

### 搜索壳层
搜索壳层继续保留现有结构，但视觉改为：

- 搜索区像一张精致的纸面卡片
- 搜索轮廓线从亮白描边改成浅暖灰描边
- 输入框文字与 placeholder 改为高可读的深棕灰 / 灰棕
- 下拉菜单和 suggestions 改成亮色浮层，保留足够层次与 hover 区分
- AI 激活态保留强调，但用柔和暖色高亮，不再使用偏冷高亮

### 搜索预览卡片
AI search preview 当前偏深色浮层，亮色版应改为：

- 暖白主卡片
- 信息分区用浅米色底和轻边框分隔
- 按钮分成明确主次：主按钮温润、次按钮轻纸片化
- 相关搜索 / 候选网站卡片统一为亮色卡片体系

### 设置弹窗
设置弹窗仍然保留在主页体系内，但视觉从深色面板改成亮色浮层：

- 弹窗背景改为暖白纸面
- 表单输入框改为浅底亮色控件
- section 边界更轻，减少“设置后台”的生硬感
- 状态提示在亮色下保持清楚但不刺眼

## 2. `src/pages/sidebar/index.html` + `src/pages/sidebar/index.css`

### 总体气质
sidebar 从冷调深色 AI 面板改成暖纸风聊天助手：

- 整体仍然是 AI 助手，但更像阅读协作界面
- 视觉重点放在消息流和输入区
- 顶栏、状态胶囊、状态卡、trace 和工具回执统一进入亮色体系

### 顶栏
- 顶栏底色改为浅暖白或半透明暖白
- 状态胶囊用浅色底 + 深色文字
- 顶栏按钮改为轻纸片按钮，而不是深色悬浮按钮
- 当前页面标题、URL 继续保留，但弱化成亮色下的次级信息

### 聊天气泡与消息区
- assistant 气泡：暖白或浅米色卡片
- user 气泡：比 assistant 略深一点的暖色浅底，保留区别但不过分跳脱
- tool_result：更像系统回执纸条，而不是深色终端块
- 消息区背景改为浅色容器，滚动区保持足够层次

### 输入区
- 输入区改成纸感书写面板
- textarea 背景更亮、边框更轻
- 提交按钮使用暖色强调
- quick actions 变成浅纸片按钮，hover 时稍微加深，不出现深色块跳变

### 锁定态 / 错误态卡片
- 继续保留原有结构和按钮关系
- 改成浅色 onboarding / 提示卡，而不是深色告警面板
- error / degraded 通过暖红、浅琥珀等方式表达，不使用浓重暗色背景

### Trace 区
执行轨迹仍可保留现有结构，但视觉调整为：

- 更浅的背景卡
- 更弱的轨道线
- 更柔和的节点色
- 文本优先可读，不做重型日志感

## 3. HTML 级适配
如亮色主题落地后需要同步浏览器控件语义，可更新：

- `src/pages/newtab/index.html`
- `src/pages/sidebar/index.html`

中的 `meta color-scheme` 从 `dark` 改为更适合亮色主题的值（例如 `light` 或 `light dark`，以最终浏览器表现为准）。

这个调整仅用于主题适配，不应引入结构变化。

## 实施策略

1. **先统一 token 层**
   - 为 newtab 和 sidebar 分别把根级颜色变量切换到暖纸风
   - 保持现有 class/state 体系不变

2. **再修核心容器**
   - 背景
   - 主卡片
   - 顶栏
   - 输入区
   - 按钮

3. **最后修次级区域**
   - 预览卡片
   - dropdown
   - suggestions
   - 状态卡
   - trace
   - tool_result

4. **只做轻量精修**
   - 可以调整留白、圆角、边框粗细、阴影扩散半径
   - 不改变布局骨架和交互入口位置

## 风险与约束

### 1. 亮色下的可读性风险
当前很多文本、边框和状态色是为深色背景设计的。切到亮色时，必须逐项检查：

- placeholder 是否过浅
- 次级文案是否掉对比
- hover/disabled/focus 是否还能被感知
- error/success 是否在亮底上足够清晰

### 2. 主题统一风险
如果只改 sidebar，不改 newtab，会造成同一 worktree 下产品割裂。用户已经明确要求“整个 worktree”，因此 newtab 与 sidebar 必须一起统一。

### 3. 不应借机扩 scope
本轮只是视觉主题切换与轻量 refinement，不应顺手新增动效、改信息架构或重写聊天布局。

## 验收标准

完成后应满足：

1. newtab、侧边栏、设置弹窗都切换为统一的暖纸风亮色主题。
2. 现有交互流程不变，功能行为不变。
3. 侧边栏消息区、输入区、状态卡和 trace 在亮色下依然清晰可读。
4. 搜索框、下拉菜单、AI preview、设置弹窗在亮色下保持足够层次。
5. 整体看起来更明亮、更柔和、更有纸感，但仍保留 AI 助手产品气质。
6. 没有出现“局部亮色、局部深色”的割裂状态。

## 验证方式

### 手动视觉检查
至少检查以下场景：

- newtab 默认态
- newtab 设置弹窗打开态
- AI search preview 展开态
- sidebar 已连接聊天态
- sidebar locked/error 状态
- sidebar 输入、quick actions、tool_result、trace 显示态

### 回归验证
沿用仓库现有 smoke test：

```bash
python .tmp/verify_newtab_extension.py
```

这个测试主要覆盖 newtab 主流程，确认亮色改动没有破坏主页渲染、设置打开/关闭和默认搜索流程。侧边栏部分需要额外手动验证亮色表现。

## 实施结论

推荐把这次任务视为一次 **暖纸风亮色主题统一与表面精修**：

- 先统一 theme token
- 再修 newtab 和 sidebar 的主要视觉容器
- 最后补齐 dropdown、preview、状态卡和 trace 等次级区域

最终结果应是：整个 `ai-sidebar-mvp` worktree 变得更明亮、更温和、更有阅读感，同时仍然像一个精致的 AI 搜索 / 对话助手，而不是后台面板或纯视觉概念稿。
