# Midnight Console Synthwave UI 重设计

- 日期：2026-05-13
- 工作目录：`D:\proj\test`
- 状态：已确认设计方向，等待用户审阅

## 1. 背景

当前界面已经具备基本功能，但整体视觉语言仍以暖纸感、浅底色、柔和棕色阴影和较重的卡片感为主：

- `src/pages/newtab/styles/index.css` 仍然是暖米色 / 奶油金 / 纸感背景体系；
- `src/pages/sidebar/index.css` 仍然是浅色纸面和暖棕玻璃拟态体系；
- `newtab` 作为首页入口，品牌识别度不够集中；
- `sidebar` 作为高频 AI 工具面板，当前更像说明卡或功能面板，而不是专业工作台。

用户已明确新的审美和产品方向：

- 采用 80 年代复古未来主义（Synthwave）语言；
- 但落地方式必须是 **克制的高可用工具型**；
- 不做高饱和、满屏发光、海报式的主题皮肤；
- 要让 `newtab` 和 `sidebar` 共享统一品牌，但职责不同。

因此，本轮设计不是追加功能，而是将现有 UI 整体重构为：

> 一个以 Synthwave 为视觉母体、以夜间 AI 控制台为产品形态的统一界面系统。

## 2. 设计目标

本轮重设计必须同时满足以下目标：

1. **统一品牌语言**
   - `newtab` 与 `sidebar` 共享同一套深色、霓虹、夜间控制台语言；
   - 不再出现首页与侧栏像两个不同产品的感受。

2. **风格可辨识，但不影响效率**
   - 用户一眼能感受到复古未来主义氛围；
   - 但核心操作和信息层级仍然优先于风格表达。

3. **首页负责氛围，侧栏负责效率**
   - `newtab` 承担品牌入口和主搜索入口；
   - `sidebar` 承担持续对话、状态反馈和高频操作。

4. **从暖纸感切换到夜间控制台**
   - 替换现有米色 / 棕色 / 纸感视觉基线；
   - 建立深紫黑、霓虹描边、低频 glow 的新体系。

## 3. 非目标

本次设计不包含以下内容：

- 不新增 AI 业务能力；
- 不改搜索决策协议、接口设置逻辑或数据结构；
- 不把整个界面做成重度场景插画或高动态海报；
- 不让 `sidebar` 承担大面积 Synthwave 场景背景；
- 不在本轮引入复杂 3D、视频或高频动画系统。

## 4. 总体方向

最终方向定义为：

> **Midnight Console**

这是一个从 Synthwave 中提取而来的产品化方向，强调：

- 深紫黑夜景基底；
- 电光蓝 / 洋红作为少量高亮；
- 低频发光、细描边、强焦点；
- 背景负责气质，控件负责效率；
- 复古元素只作为品牌信号，不作为主信息载体。

### 4.1 关键词

- 夜间
- 精密
- 克制
- 未来
- 冷静
- 高对比
- 工具型

### 4.2 明确避免

- 满屏高饱和粉紫和青蓝；
- 大面积厚玻璃拟态；
- 暖棕纸面感；
- 过多装饰卡片；
- 高频闪烁和强表演性动画；
- 让复古元素压过输入框、消息内容和状态信息。

## 5. 页面职责划分

### 5.1 `newtab`

`newtab` 是品牌入口和主搜索操作台，应承担：

- Synthwave 氛围的主要承载；
- 页面首屏的品牌辨识；
- 搜索入口和 AI 搜索增强的清晰主操作；
- 轻量的分析反馈与建议展开。

设计原则：

- 远景允许存在 Synthwave 场景元素；
- 近景必须高度收敛；
- 搜索框是绝对第一视觉中心；
- 其他一切都从属于搜索行为。

### 5.2 `sidebar`

`sidebar` 是 AI 工作侧台，应承担：

- 与当前页面相关的高频聊天；
- AI 状态与页面状态的轻量反馈；
- 工具动作回执和执行轨迹；
- 紧凑、稳定、长期可用的工作流界面。

设计原则：

- 不做海报式场景；
- 不引入显眼太阳、地平线、棕榈树等具象符号；
- 保留深色控制台气质和霓虹交互信号；
- 把所有装饰退到正文和操作之后。

## 6. 配色系统

本轮设计采用 **90% 深色中性基底 + 10% 霓虹强调色** 的结构。

### 6.1 基础色

- 页面主背景：`#07030f`
- 深紫背景过渡：`#140a24`
- 一级面板：`#12091f`
- 二级面板：`#181129`
- 分层深底：`#1f1733`

### 6.2 文字色

- 主文字：`rgba(236, 232, 255, 0.92)`
- 次文字：`rgba(184, 176, 214, 0.72)`
- 弱提示：`rgba(150, 142, 186, 0.56)`

要求：

- 大段正文只能使用中性高可读文本色；
- 不允许用 `#00ffff` 或 `#ff00ff` 直接承载正文阅读内容。

### 6.3 强调色

- 主焦点 / ready：`#00ffff`
- AI 强调 / active：`#ff00ff`
- 品牌 CTA 渐变：`#ff6b35 -> #f72585`
- 警告：`#ffb347`
- 错误：偏洋红红系，不用纯正红

### 6.4 边界与发光

- 常态描边：`rgba(0, 255, 255, 0.18)`
- hover / focus 描边：`rgba(0, 255, 255, 0.42)`
- active / AI 状态描边：`rgba(255, 0, 255, 0.46)`
- 外发光必须小半径、低透明，像精密设备而不是霓虹招牌。

## 7. 材质与背景系统

### 7.1 `newtab` 背景

`newtab` 背景采用三层结构：

1. **远景天空层**
   - 深紫黑渐变天空；
   - 允许极淡星点或环境光晕。

2. **品牌符号层**
   - 条纹切割的复古太阳；
   - 极低对比透视网格地面；
   - 可选极淡城市线或地平线结构。

3. **内容保护层**
   - 中轴区域保持更干净、更稳定；
   - 保证搜索框后方不出现高对比纹理与强亮部。

原则：

- 背景元素只存在于远景；
- 不与搜索框轮廓竞争；
- 不形成多块独立装饰对象。

### 7.2 `sidebar` 背景

`sidebar` 不使用完整场景层，而是采用：

- 深紫黑渐变底；
- 极淡扫描线或 CRT 横纹；
- 局部冷色 glow；
- 极弱噪点或材质纹理。

原则：

- 让用户感受到控制台环境；
- 不让背景进入内容阅读层。

## 8. 排版系统

### 8.1 标题和品牌字

标题与品牌可参考 Orbitron / Audiowide 一类的几何无衬线气质，但不要求强制替换整个系统字体。

建议：

- 首页品牌字或局部强调标题可使用更强的未来感造型；
- 金属渐变或 chrome 风格只用于极少数品牌信号；
- 不将这种风格用于正文、表单、消息气泡。

### 8.2 正文与功能文本

- 保持高可读中文无衬线；
- 正文字重稳定；
- 说明文案缩短，减少教程感；
- 少用过度装饰的大写眉题和长句解释。

## 9. `newtab` 布局重构

### 9.1 主结构

`newtab` 应重构为三层：

1. **远景品牌背景层**
2. **核心搜索操作层**
3. **响应反馈展开层**

### 9.2 搜索为绝对中心

搜索框应成为首屏唯一明确主焦点：

- 放在首屏中轴偏上；
- 外轮廓更清晰、更利落；
- 深色实体底 + 细霓虹描边；
- focus 时出现受控的 cyan glow。

### 9.3 工具入口收敛

以下入口应统一为一组紧凑图标控件：

- AI 开关
- 打开 AI sidebar
- 设置

要求：

- 默认安静；
- hover / active 才增强亮度；
- 作为辅助控制，不应压过搜索框。

### 9.4 AI Preview 重构

`ai-search-preview` 应从“独立说明卡”调整为“搜索框下方的分析面板”：

- 更像控制台分析结果；
- 更靠近输入行为；
- 默认隐藏；
- 仅在 AI 开启且产生结果时展开。

### 9.5 搜索建议和目标下拉

- 保持紧贴搜索框展开；
- 列表项默认深色低对比；
- hover 时通过细描边、微光和窄高亮区分；
- 避免大面积浅色铺底。

## 10. `sidebar` 布局重构

### 10.1 顶部栏

顶部区域改成更薄的系统状态栏，而不是头部展示卡：

- 左：助手身份或轻量标题
- 中：当前页面 / AI 状态
- 右：设置按钮

要求：

- 压缩垂直体积；
- 减少大块背景和厚阴影；
- 页面标题与 URL 弱化，不占主视觉。

### 10.2 消息区

消息流是侧栏主内容区：

- assistant 消息最稳定；
- user 消息更轻、更短；
- tool result 作为 AI 动作回执并入消息流；
- trace 作为窄日志条或弱层级结构，不单独形成大卡片模块。

### 10.3 输入区

输入区应像 AI 控制台输入器：

- 深色底；
- 较收敛的圆角；
- 聚焦时 cyan glow；
- 快捷操作做成紧凑 chip；
- 发送按钮是少数可以使用 sunset 渐变的地方。

### 10.4 状态面板

未配置、错误、degraded 等状态保留，但改造成系统面板：

- 更短的标题；
- 更短的说明；
- 更明确的主次操作；
- 避免教程式长段落和大面积暖色卡片。

## 11. 组件设计规范

### 11.1 按钮

- 默认按钮：深色底 + 细 cyan 描边；
- hover：描边提亮，出现薄外发光；
- active：轻微下沉；
- 主按钮：少量使用 `#ff6b35 -> #f72585` 渐变；
- 次按钮：回到深色控制台语义，不再使用浅色暖底胶囊。

### 11.2 输入框

- 背景：`#12091f` 或 `#181129`
- 边框：低透明 cyan
- focus：提亮描边 + 小半径 glow
- placeholder：低对比冷灰紫
- 圆角建议统一在 `14px` 到 `18px`

### 11.3 面板

- 只在必要时使用面板；
- 深色硬表面；
- 细描边；
- 极浅内高光；
- 冷色短阴影；
- 靠间距和边界分层，不靠大面积不同底色。

### 11.4 状态条

- 小圆点 + 短文本；
- ready：cyan；
- AI active：magenta；
- warning：orange；
- error：洋红红；
- 尽量薄，不做大胶囊。

### 11.5 消息气泡

- user：偏紫深底，边框更弱；
- assistant：偏蓝黑深底，边框更清晰；
- tool result：窄条、信息密度更高；
- 正文不加 glow；
- 仅标签、状态词或少量关键节点允许高亮色。

### 11.6 下拉、建议和快捷动作

- 常态安静；
- hover 再增强；
- 可用细霓虹边线或窄高亮区代替大面积背景变化；
- 保持紧凑命令式语言。

## 12. 动效原则

动效必须低频、慢速、可关闭，推荐仅保留以下类型：

- 网格或背景缓慢流动；
- 状态灯脉冲；
- 霓虹 focus glow；
- AI 开关的轻微 pulse；
- 太阳或环境光的极慢呼吸。

明确禁止：

- 高频闪烁；
- 大范围彩色扫光；
- 对消息阅读产生干扰的持续动画；
- 会让输入、列表或状态面板抖动的反馈方式。

## 13. 现有实现中的替换重点

### 13.1 `newtab`

当前样式中以下方向应被移除或显著弱化：

- 暖米色 / 奶油金背景基线；
- 暖棕阴影；
- 纸张与柔雾的主风格地位；
- 浅色搜索框和浅底弹层；
- 暖色按钮体系。

应新增或重构：

- 夜间背景 token；
- 条纹太阳与低对比网格；
- 深色搜索框和统一霓虹焦点体系；
- 深色 AI preview / dropdown / settings 视觉。

### 13.2 `sidebar`

当前样式中以下方向应被移除或显著弱化：

- 浅色纸面背景；
- 暖色卡片和厚重圆角；
- 棕色系按钮与输入框；
- 大面积软玻璃卡片感；
- 顶部头区过重的展示感。

应新增或重构：

- 深色控制台基底；
- 薄状态栏；
- 深色消息区；
- 深色输入器；
- 系统化状态面板；
- 更紧凑的 trace 表达。

## 15. 验收标准

重设计完成后，应满足以下结果：

1. `newtab` 与 `sidebar` 在视觉上属于同一品牌体系；
2. 首页第一眼是深色 Synthwave 控制台，而不是暖纸感页面；
3. 搜索框成为 `newtab` 的绝对主视觉中心；
4. `sidebar` 第一感觉是专业 AI 工作侧台，而不是说明卡或功能面板；
5. 电蓝 / 洋红只承担焦点与状态强调，不污染正文阅读；
6. 背景、动效和装饰不会影响输入、阅读和状态识别；
7. 风格辨识度明显提升，但整体仍然克制、可长期使用。

## 16. 实施建议

建议按以下顺序实施：

1. 先建立统一 design tokens；
2. 重构 `newtab` 背景层与搜索框层级；
3. 重构 `sidebar` 顶栏、消息区、输入区与状态面板；
4. 统一按钮、输入框、下拉和提示组件；
5. 最后补充低频动效、扫描线纹理和细节 glow。

本任务应被视为一次完整的视觉系统切换，而不是局部美化。
