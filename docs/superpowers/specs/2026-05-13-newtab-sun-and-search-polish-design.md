# Newtab 太阳与搜索框精修设计

- 日期：2026-05-13
- 工作目录：`D:\proj\test`
- 状态：已确认 `Solar Monolith / Synthwave Scene` 方向，等待用户审阅

## 1. 背景

当前 `newtab` 已经完成 Midnight Console 基础改版，但仍有几处关键视觉问题没有收干净：

- 背景存在明显横向割裂和色差，远看像拼接层，而不是连续空间；
- 太阳主体已经存在，但体积感和分层语言还不够精细；
- 搜索框的边框动画被当前结构遮挡，动效成立但表现不完整；
- 页面氛围动态偏少，缺少“页面活着”的低频环境反馈。

用户已明确新的精修方向：

- 继续保留 Midnight Console / Synthwave 基线；
- 太阳主配色采用 **亮橙粉**；
- 动画强度采用 **第 2 档：克制耐看**；
- 太阳分层参考提供的 synthwave 示例图；
- 搜索框应继续保持页面第一焦点，不被背景和动效压住。
- 场景装饰方向采用 **偏 synthwave 场景装饰**；
- 场景强度采用 **第 2 档：明显有场景感，但不做海报化**。

因此，本轮不是再次大改首页结构，而是对现有 `newtab` 做一次范围明确的视觉精修：

> 修正背景连续性，重做太阳分层语言，重构搜索框 HUD 边框层，并补齐克制型环境动画。

## 2. 设计目标

本轮精修必须同时满足以下目标：

1. **背景从拼接感变成连续空间**
   - 页面应读作一张完整夜空，而不是多块横向渐变并置。

2. **太阳成为高质量品牌符号**
   - 太阳必须先以完整光体成立，再用细密水平切片雕刻表面。

3. **搜索框仍是绝对第一焦点**
   - 背景和太阳负责远景氛围；
   - 搜索框的轮廓、输入区和动效必须清楚、完整、无遮挡。

4. **补足页面生命感，但不做高频表演**
   - 页面要有低频环境动效；
   - 不能做成噪音大、长期停留疲劳的 landing page。

## 3. 非目标

本轮不包含以下内容：

- 不修改搜索、建议、AI preview 的业务逻辑；
- 不将 `newtab` 改造成完整 marketing/landing page；
- 不把太阳分层条纹铺满整个屏幕；
- 不引入高频 CRT 全屏闪烁；
- 不改 `sidebar`；
- 不增加新的面板、卡片区或大块内容模块。

## 4. 方案对比与选择

### 方案 A：仅修背景色差，不动太阳与搜索框结构

优点：

- 改动小；
- 风险最低。

缺点：

- 解决不了太阳质感问题；
- 解决不了搜索框边框动画被遮挡的问题；
- 页面整体提升不够明显。

不采用。

### 方案 B：做完整海报化 synthwave 场景

优点：

- 第一眼更强烈；
- 风格辨识度更高。

缺点：

- 容易压过搜索框主操作；
- 长期使用更容易疲劳；
- 与工具型 `newtab` 的职责不符。

不采用。

### 方案 C：保持 Midnight Console 骨架，做精修级重构

构成：

- 连续深夜天空；
- 亮橙粉太阳；
- 太阳内部细密水平分层；
- 低频扫描线、地平线和网格动效；
- 搜索框独立 HUD outline 层。

优点：

- 视觉问题能一次性收干净；
- 仍然保持工具型首页的稳定感；
- 能保留当前重设计成果，不推翻结构。

但在进一步审阅后，方案 C 还需要继续收束视觉重心，避免背景元素和控制按钮继续分散主焦点。因此最终在方案 C 的基础上，确定采用更明确的收敛版本。

## 5. 最终视觉方向

最终方向定义为：

> **Solar Monolith / Synthwave Scene**

它不是海报式复古页面，而是一个以搜索框为唯一主操作中心、以完整太阳为品牌符号，并且明显带有 synthwave 场景气质的夜间搜索控制台。

### 5.1 关键词

- 连续
- 精密
- 夜间
- 一体化
- 单体设备感
- 亮橙粉热源
- 场景感
- 轨道光环
- 地平线热雾
- 低频动效
- HUD
- 克制

### 5.2 明确避免

- 横向拼接感；
- 粗条纹大断层；
- 搜索框边框被遮挡；
- 整屏高强度扫描线；
- 大幅呼吸、漂浮、闪烁；
- 把背景做得比搜索更像主角。

## 6. 布局与层级

页面必须先读出一个中心装置，再读出背后的品牌热源。

### 6.1 主体布局

- 页面中心轴固定在搜索框；
- 太阳与搜索框共享同一垂直中线；
- 太阳位于搜索框后上方，作为远景热源；
- 搜索框位于首屏视觉中心略偏下；
- AI preview 继续挂在搜索框下方，但视觉重量必须低于输入区。

### 6.2 桌面尺寸建议

- 太阳直径：`340px - 380px`
- 搜索框总宽：`680px - 760px`
- 搜索组件总高：`92px - 108px`
- 太阳底边与搜索框顶部之间应保留明确呼吸距离，不可贴近到形成压迫。

### 6.3 移动端尺寸建议

- 太阳直径：`180px - 220px`
- 搜索框宽度：`calc(100vw - 24px)`
- 搜索组件必须保持一体式，不再拆成上方漂浮胶囊和下方输入框两段；
- 控制带保留，但高度更薄。

## 7. 背景系统重构

背景系统保持三层，但重新定义各层职责。

### 7.1 夜空底层

职责：

- 提供一张连续的纵向深夜天空；
- 清掉当前“横向色块断层”的观感。

设计要求：

- 以纵向深色渐变为主；
- 允许少量大范围径向辉光；
- 所有大色块过渡必须是柔和连续的；
- 亮部主要集中在太阳上方和周边，而不是从左到右切分。

建议底色范围：

- 顶部：`#08101d`
- 中段：`#0a1322`
- 底部：`#070b14`

效果目标：

- 即便暂时隐藏太阳和网格，背景本身也应像完整夜空成立。

### 7.2 远景氛围层

职责：

- 提供少量星点、辉光和空间层次。

设计要求：

- 星点稀薄；
- 辉光低透明；
- 只能辅助，不可形成第二视觉中心。

增强要求：

- 允许加入极少量流星式亮线；
- 允许加入大尺度但低透明的暖雾与冷雾；
- 场景应明显比上一版更有“远处正在发光”的感觉，但不能读成动态壁纸。

效果目标：

- 页面看起来不是死背景，但也不显花。

### 7.3 地平线与网格层

职责：

- 强化 retro-futurist 语言；
- 与太阳形成经典 synthwave 地平线结构。

设计要求：

- 地平线为细线，低频微闪；
- 网格透视存在，但对比弱；
- 动作只做慢速滚动；
- 不得干扰搜索框区域文字可读性。

增强要求：

- 地平线下方允许出现暖雾带与热浪式柔光；
- 网格前方允许出现低对比的前景剪影；
- 这些元素必须只框景，不得挡住搜索框轮廓和文字。

规则：

- 不允许左右大色块对撞；
- 不允许背景形成第二个亮中心；
- 网格应处于“可感知但不抢眼”的透明度范围。

## 8. 太阳设计

太阳是本轮最核心的品牌符号，必须按以下结构成立。

### 8.1 体积优先

太阳先以完整发光圆盘成立：

- 整体是一个完整圆形热源；
- 主配色为亮橙粉；
- 上半部更完整、更明亮；
- 下半部向粉色与暗部过渡。

原则：

> 先有完整太阳体积，再做表面分层。

建议主色：

- 高光：`#fff0b8`
- 主橙：`#ffb36b`
- 过渡橙粉：`#ff8c7e`
- 深粉：`#ff5d98`

### 8.2 水平分层

太阳分层参考用户确认的 synthwave 示例图。

正确做法：

- 细密的水平条纹/切片覆盖在太阳内部；
- 条纹铺满太阳可见区域；
- 条纹用于雕刻太阳表面，而不是把太阳切成几个粗块。

明确限制：

- 太阳分层条纹不铺满整个屏幕；
- 页面全屏最多只有一层极淡扫描线，不与太阳分层混用。

### 8.3 分层密度

要求：

- 比当前方案更细；
- 比参考 landing page 的大切口更精密；
- 远看先读成太阳，近看再读出条纹层。

效果目标：

- 不出现“粗条纹块感”；
- 不出现“切坏了的太阳”；
- 保持高质量的 retro sun 语言。

条纹规则：

- 单条高度更细；
- 明暗对比比当前方案更低；
- 远看先是完整热源，近看再读出雕刻感。

### 8.4 外发光

- 外发光范围应比当前方案更大；
- 发光亮度应比当前方案更低；
- 目标是形成更柔和的热源晕染，而不是廉价霓虹描边。

### 8.5 太阳外圈装饰

- 太阳外圈允许加入 `2 - 3` 层不完整弧环；
- 弧环应读成轨道或能量环，而不是完整几何描边；
- 弧环透明度低于太阳主体，速度慢于 outline sweep；
- 弧环只能强化 synthwave 品牌感，不能让太阳外圈比太阳本体更亮。

### 8.6 太阳动画

太阳只允许低频动效：

- 轻微呼吸；
- 条纹层极弱亮度漂移；
- 不做强烈闪动和形变。

目标：

- 页面持续停留时有生命感；
- 但用户不会被太阳持续打扰。

## 9. 搜索框重构

搜索框是页面主操作区，必须从背景语言中被明确保护出来。

### 9.1 问题定义

当前问题不是“没有描边”，而是：

- outline 动画与搜索框结构耦合过深；
- 描边层被现有容器关系遮挡；
- 最终造成动效存在但不完整。

同时，当前上方独立按钮胶囊条与主输入框读起来像两个分离组件，不利于形成完整设备感。

### 9.2 新结构

搜索区应重构为单一的一体式组件，不再保留“上方漂浮胶囊条 + 下方输入框”的两段式关系。

建议组件结构：

1. `search-shell`
2. `search-outline-layer`
3. `search-body`
4. `search-control-rail`
5. `search-main-row`

职责如下：

1. **search-outline-layer**
   - 负责完整可见的 HUD 轮廓和扫光动画。

2. **search-body**
   - 负责深色实体面板、阴影、输入内容和整体承载。

3. **search-control-rail**
   - 顶边内嵌的薄控制带，放置 `AI toggle / AI sidebar / settings`。

4. **search-main-row**
   - 负责左侧搜索目标与右侧输入框。

原则：

- outline 层不再依附容易裁切的内部结构；
- 控制按钮不再作为漂浮附件存在；
- 搜索框必须读起来像页面中央的一件完整设备；
- 页面任何背景层都不应压住它。

### 9.3 视觉要求

- 搜索框本体保持深色、稳定、安静，建议主体底色接近 `#101826`；
- 顶部略亮，底部略暗，形成轻微体积感；
- 外 outline 必须细、亮、完整，但亮度克制；
- 输入区必须是整个页面的绝对第一焦点；
- 控制带视觉权重低于主输入区；
- focus 和 AI 状态可略增强 glow，但不能让文字发虚。

### 9.4 Outline 与状态

搜索框动效采用克制策略：

- 默认 outline 可见；
- hover 略增强；
- focus 明显增强；
- AI searching 时只提升局部亮度，不扩大整体发光面积；
- 使用一段沿轮廓慢速运动的细扫光，而不是整圈高亮跑马灯。

### 9.5 动画要求

- 一段流动高光；
- 低速；
- 透明度受控；
- hover/focus 时略增强。

不做：

- 高频脉冲；
- 多圈跑马灯；
- 粗发光边框。

## 10. 控制带与按钮系统

控制带的目标是精密，不是抢戏。

### 10.1 控制带规则

- 高度薄；
- 对比低于主输入区；
- 与搜索框本体共用一套半径、描边和材质语言；
- 读起来像设备顶部状态区，而不是独立漂浮附件。

### 10.2 按钮规则

- `AI toggle` 保留动态，但收敛成更克制的环形活动；
- `AI sidebar` 与 `settings` 为同级次按钮；
- 图标风格必须统一；
- 所有按钮状态变化必须清楚，但不得比输入区更亮。

## 11. 动画策略

本轮整体动画强度采用用户确认的 **第 2 档：克制耐看**。

### 11.1 保留的动画

- 太阳微呼吸；
- 太阳分层极轻亮度漂移；
- 太阳外圈弧环极慢漂移或亮度起伏；
- 地平线低频微闪；
- 网格慢滚；
- 稀疏流星线或星轨慢速掠过；
- 地平线暖雾与热浪轻微漂移；
- 全屏低透明扫描线缓扫；
- 搜索框 outline 流动高光。

建议时长：

- hover / focus：`180ms - 240ms`
- outline sweep：`4.5s - 6s`
- 太阳呼吸：`14s - 18s`
- 弧环漂移：`20s - 28s`
- 网格漂移：`18s - 24s`
- 流星线掠过：`16s - 24s`

### 11.2 不采用的动画

- 全屏 CRT 高频闪烁；
- 大幅上下漂浮；
- 高强度霓虹脉冲；
- 高频闪断式故障效果；
- 与搜索输入行为无关的强表演性动画。

### 11.3 动画原则

动画的作用是：

- 让页面“活着”；
- 强化夜间控制台气质；
- 增加精密感。

动画不应承担：

- 抢第一眼；
- 填补布局问题；
- 制造噪音式刺激。

## 12. 配色系统

本轮配色应从“偏青蓝发光的整体氛围”收敛成“热源橙粉 + 控制台冷蓝”的双主轴。

### 12.1 角色分工

- 背景：深蓝黑
- 品牌热源：橙粉
- 交互高亮：冷青蓝
- 场景雾光：低透明暖橙与低透明洋红
- 主文本：偏冷白
- 次级文字：雾蓝灰

### 12.2 原则

- 功能颜色必须分工明确；
- 不允许页面中所有层都在发光；
- 不允许控制按钮、背景辉光和搜索 outline 争抢同一亮度层级。

## 14. 验证要求

本轮实现完成后，验证应覆盖以下内容：

1. **背景连续性**
   - 页面不再有明显横向断层或色块拼接感。

2. **太阳视觉契约**
   - 太阳为完整圆盘；
   - 内部存在细密水平分层；
   - 主配色为亮橙粉。

3. **搜索框 outline 完整性**
   - 边框动画完整可见；
   - 不被壳体、背景或其他层裁切。

4. **搜索框一体化**
   - 顶部控制按钮已并入搜索组件；
   - 搜索区不再读成上下两个漂浮部件；
   - 输入区仍然是唯一明确主焦点。

5. **移动端稳定性**
   - 太阳不会缩成装饰性小圆点；
   - 搜索组件在窄屏下仍保持完整结构；
   - 触达尺寸与间距符合移动端使用要求。

6. **场景装饰成立**
   - 可以明确读出 synthwave 场景，而不只是深色搜索页；
   - 太阳外圈、暖雾、天空细节或前景剪影至少有两类成立；
   - 装饰不压过搜索框主焦点。

7. **动效节奏**
   - 页面存在低频环境动效；
   - 不出现高频干扰感。

8. **业务不回退**
   - 搜索、建议、AI preview、设置入口行为保持稳定。

## 15. 成功标准

当以下条件同时满足时，本轮设计视为成功：

- 用户不再感到背景有明显割裂色差；
- 太阳被明确识别为高质量的完整热源，而不是粗条纹块；
