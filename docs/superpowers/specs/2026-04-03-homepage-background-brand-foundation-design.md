# 主页背景重构（纯 CSS 品牌底座）设计

- 日期：2026-04-03
- 工作目录：`D:\proj\test\.worktrees\ai-sidebar-mvp`
- 状态：已确认设计方向，等待用户审阅

## 1. 背景与决策

当前新标签页主页背景使用 `src/pages/newtab/liquid-glass-bubble-layer.mjs` 提供的运行时液态玻璃效果，配合 `src/pages/newtab/styles/index.css` 中的多层暖色背景共同形成页面氛围。

用户明确要求：

- **不修复现有液态背景 bug**；
- **直接整体重构背景系统**；
- 保留当前这套 **暖米色 / 奶油金 / 柔雾纸感** 的颜色方向；
- 当前阶段 **不做动态**；
- 后续可能新增 **壁纸** 或其他主页模块，因此新方案必须稳定、可扩展、不会与内容层打架。

基于这些约束，本设计采用：

> **纯 CSS 品牌底座背景**

这不是对现有特效的局部修补，而是将背景从“运行时图形系统”重构为“稳定的样式层系统”。

## 2. 设计目标

新背景必须同时满足以下目标：

1. **稳定优先**
   - 不再依赖 Three.js、shader、droplet、canvas 的运行时背景逻辑。
   - 背景应退化为普通样式系统的一部分，避免渲染链路、状态同步、重绘时序导致的视觉异常。

2. **保留现有气质**
   - 保留当前用户认可的暖米色、奶油金、纸面感、柔雾感。
   - 去除“液态折射感”“漂浮对象感”“正在表演的特效感”。

3. **搜索框始终是第一视觉中心**
   - 背景只托住内容，不抢主视线。
   - 中央搜索区应最干净，层次主要分布在外围。

4. **为未来扩展留接口**
   - 将来新增壁纸层、推荐模块、侧边栏、卡片区时，不需要推翻背景系统重做。
   - 当前先做静态，但结构上允许后续演进。

## 3. 非目标

本次设计不包含以下内容：

- 不修复现有 liquid-glass 背景 bug；
- 不保留旧背景的动态表现；
- 不新增运行时动画系统；
- 不在本次设计中引入图片壁纸功能；
- 不改搜索业务流程、AI 搜索逻辑、设置表单逻辑；
- 不顺带做与背景无关的视觉大改版。

## 4. 方案对比与选择

### 方案 A：纯 CSS 品牌底座（采用）

使用纯 CSS 渐变、伪元素、静态纹理与柔光层构建完整背景底板。

**优点：**
- 最稳定；
- 最容易维护；
- 与未来模块兼容性最好；
- 不再依赖图形渲染生命周期；
- 最容易控制层级与可读性。

**缺点：**
- 视觉记忆点弱于特效型背景；
- 质感主要依赖配色、层次和节制的细节控制。

### 方案 B：品牌底 + 壁纸插槽体系（本次不采用）

从第一阶段就内建完整壁纸层。

**不作为本次直接目标的原因：**
- 用户当前优先级是先把背景系统稳定下来；
- 壁纸功能尚未进入实现阶段，过早做状态体系会引入额外复杂度；
- 更适合作为纯 CSS 品牌底座完成后的第二阶段演进。

### 方案 C：静态插画式主视觉（不采用）

使用明显图形或抽象插画作为背景主体。

**不选原因：**
- 更容易抢搜索框；
- 与未来壁纸、模块扩展冲突更大；
- 不符合“保留现有配色气质，但更稳”的目标。

## 5. 最终视觉方向

新背景视觉语言定义为：

> **温润、安静、连续的纸面空间**

关键词：

- 暖米色
- 奶油金
- 柔雾
- 纸张质感
- 低对比、低频层次
- 非对象化、非特效化

明确避免：

- 液体折射感
- 玻璃球 / 泡泡 / 漂浮对象感
- 高频细节
- 小而亮的高对比点
- 锐利边界
- 中央强聚光
- 会和输入框边缘竞争的明暗条带

## 6. 背景分层结构

背景系统只保留 4 个视觉层，全部以 CSS 实现。

### 6.1 Base 底色层

**职责：** 提供页面最稳定的暖米色主底。

**设计要求：**
- 由 1 个主线性渐变 + 1~2 个极弱的大面积径向渐变构成；
- 明暗变化必须大块、缓慢、连续；
- 去掉任何会被感知为“图形对象”的中心团块。

**效果目标：**
即使临时关闭所有上层细节，这一层本身也能作为完整背景成立。

### 6.2 Paper Texture 纸面纹理层

**职责：** 提供温润材质感，让背景不像数码塑料渐变。

**设计要求：**
- 纹理极轻；
- 更像纸面纤维、纸浆粗糙度、空气颗粒，而不是可辨识图案；
- 只能在停留观察时隐约可见，不能成为第一眼信息。

**效果目标：**
提升高级感，但不增加视觉噪音。

### 6.3 Soft Light 柔光层

**职责：** 增加层次，避免画面过平。

**设计要求：**
- 使用数块模糊的大面积柔光区；
- 亮区主要分布在外围，如左上、右上、下方；
- 不形成明确光束、光点或方向性强的图形。

**效果目标：**
即使完全静态，也能维持温和的空间感。

### 6.4 Focus 聚焦层

**职责：** 轻微收束视线，让搜索区自然成为中心。

**设计要求：**
- 搜索区附近更干净、略微更亮；
- 四周做极轻的收暗或杂质增强；
- 不做明显聚光灯效果。

**效果目标：**
用户会优先看到搜索框，但不会明显察觉背景在“硬引导”。

## 7. 布局与视觉原则

### 7.1 搜索框区域必须最干净

新背景不应在搜索框正后方放置明显团块、斑点、纹理峰值或装饰元素。

中心区域原则：
- 更平；
- 更轻；
- 更少对比；
- 更少边界。

### 7.2 层次重心放外围，不放中轴

背景视觉变化主要分布在：
- 左上；
- 右上；
- 页面下方；
- 边缘区域。

中轴区域只保留很弱的聚焦修正，以确保未来顶部按钮、搜索框、侧栏都不与背景冲突。

### 7.3 背景必须是“连续空间”，不是“对象集合”

用户看到的应该是一张完整纸面空间，而不是多个独立背景对象并列存在。

因此应避免：
- 泡泡感；
- 球体感；
- 片状装饰物悬浮感；
- 明显的重复几何图案。

### 7.4 为未来模块预留留白

建议将页面背景天然划分为：
- 顶部控制区：干净；
- 搜索主体区：最干净；
- 两侧次级区域：允许少量层次；
- 页面下缘：允许承担部分氛围层次。

这样将来新增模块时，背景不需要再次推翻。

## 8. 技术设计

### 8.1 实现原则

新背景采用：
- `body` 负责全局底色与全页级氛围；
- 背景容器负责承载附加静态层；
- `::before` / `::after` 负责纸面纹理层与柔光层；
- 不再初始化 WebGL / canvas / 动态 droplets。

### 8.2 现有背景容器的处理

`src/pages/newtab/index.html` 中现有背景容器节点可以保留，但职责必须改变：

- 从“动态 bubble 特效挂载点”改为“静态背景层容器”；
- 不再承载 canvas 渲染；
- 只用于承载静态视觉叠层与未来扩展插槽。

### 8.3 现有运行时代码的处理

`src/pages/newtab/liquid-glass-bubble-layer.mjs` 对应的旧背景逻辑不再属于新架构。

本设计要求：
- 移除主页对该运行时背景模块的依赖；
- 删除或停用其初始化入口；
- 让背景回归纯样式系统；
- 不再保留 droplets、shader、renderer、resize refresh 这类背景专属生命周期概念。

### 8.4 CSS 组织建议

背景样式建议按职责拆分为清晰分区：

1. 颜色 token
2. 全局底色层
3. 背景容器主层
4. 纸面纹理层
5. 柔光层
6. 聚焦修正层
7. 运行时状态微调层

要求：
- 每层职责单一；
- 命名应体现用途，而不是视觉比喻；
- 后续添加壁纸层时，能明确知道插入位置。

### 8.5 页面状态兼容策略

现有状态类如：
- `is-settings-open`
- `is-ai-sidebar-open`
- 其他已有页面状态

仍可保留，但背景只做**轻量视觉修正**，不再有单独运行时状态机。

可接受的状态反应：
- 打开设置：背景略降对比、略收暗；
- 打开 AI 侧边栏：背景做微弱平衡调整，但不发生大幅视觉切换。

明确禁止：
- 特效暂停态；
- 动态模式切换态；
- 依赖尺寸同步或手动 refresh 的背景逻辑。

## 9. 未来扩展兼容性

虽然本次只做纯 CSS 品牌底座，但新架构必须允许后续平滑扩展。

### 9.1 壁纸扩展

未来若加入壁纸，推荐插入顺序为：

- Base 底色
- Wallpaper Layer（未来新增）
- Paper Texture
- Soft Light
- Focus
- 内容层

这样即使壁纸变化，也能维持统一品牌气质与内容可读性。

### 9.2 轻动态扩展

若未来恢复非常轻的动态，只允许对 **Soft Light** 层做缓慢呼吸式变化。

不允许重新引入：
- 独立图形对象系统；
- 复杂物理模拟；
- 依赖运行时图形重绘的背景主逻辑。

### 9.3 新模块扩展

以后无论增加：
- 推荐模块；
- 侧边栏；
- 信息卡片；
- 其他主页组件；

都应直接叠加在品牌底座之上，而不是再次改造背景主体。

## 11. 验收标准

重构完成后，应满足以下标准：

1. 页面背景为完全静态的纯 CSS 品牌底座；
2. 不再出现与液态背景相关的运行时 bug 路径；
3. 搜索框仍然是页面第一视觉中心；
4. 背景整体气质延续当前暖米色、柔雾纸感方向；
5. 打开设置或 AI 侧边栏时，背景只发生轻微、稳定的样式修正；
6. 页面未来新增壁纸或模块时，不需要推翻背景系统再设计。

## 12. 风险与控制

### 风险 1：背景做得过于平，失去层次

**控制：** 依靠大块柔光层和极轻纸面纹理提供质感，不靠特效补存在感。

### 风险 2：纹理过重，导致页面脏或花

**控制：** 纹理只能作为“停留可感知”的细节，不能变成可读图案。

### 风险 3：聚焦层过强，形成明显舞台灯光

**控制：** 聚焦层只做极弱收束，必须以“不被注意到”为设计基准。

### 风险 4：未来接壁纸时破坏品牌统一性

**控制：** 未来壁纸必须插入品牌底和统一覆盖层之间，而不是替代整个背景系统。

- 不再优先修复 liquid-glass 背景；
- 直接以纯 CSS 品牌底座替换整套背景系统；
- 旧连续性修复方案不再是主路线。

后续实现计划应以本设计为准。
